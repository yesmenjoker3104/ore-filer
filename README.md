# ore-filer

Windows向けの、キーボード操作中心の2画面ファイラー。

cfilerの操作感を参考にしつつ、実装は新規に行う。GUIにはPySide6を使用し、将来的なCLI操作、assist-chat連携、Pythonプラグインによる機能追加に対応する。

## 設計方針

- 既存のcfilerコードは流用しない
- GUIはPython + PySide6で実装する
- 標準キー操作はcfilerの106キーボード設定に準拠する
- キー設定はコードに埋め込まず、外部TOMLファイルで管理する
- GUIとCLIは同じファイル操作サービスを利用する
- Pythonプラグインから機能を追加できるようにする
- ファイル操作は画面をブロックしない
- 削除、上書きなどの危険な操作は明示的に確認できるようにする
- Git操作はPythonライブラリで完結させ、`git.exe`に依存しない

## 画面構成

```text
+------------------------------------------------+
| 左ペインのパス       | 右ペインのパス          |
+----------------------+-------------------------+
| ..                   | ..                      |
| Documents            | Downloads               |
| sample.txt           | image.png               |
|                      |                         |
+----------------------+-------------------------+
| ステータスバー / 操作メッセージ                |
+------------------------------------------------+
```

- 左右のペインは同じ部品を使用する
- アクティブペインを1つ保持する
- コピー・移動先は、反対側ペインの現在ディレクトリを標準とする
- ペインの幅は変更可能にする
- ファイル一覧にはファイル名、サイズ、更新日時、ディレクトリを表示する

## Windows版exeのビルド

GitHub Actionsの`Build Windows executable`ワークフローでWindows版を作成します。

- `main`ブランチへのpushで自動実行
- Actions画面の`Run workflow`から手動実行も可能
- `v*`タグのpushでGitHub Releaseを作成し、次の2つを添付する
  - `ore-filer.exe`: 単体の本体
  - `ore-filer-Windows.zip`: `ore-filer.exe`と`app-launcher\app-launcher.exe`を含む一式（自動更新が取得するのはこちら）
- 開発時のArtifactは`ore-filer-windows`（同じ2ファイル）
- ワークフローは`yesmenjoker3104/app-launcher`をチェックアウトし、`build.ps1`で`app-launcher.exe`をビルドして同梱する

## 開発とテスト

依存関係は`.venv`に入れる。開発用の`ruff`は`dev`の任意依存として入る。

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m ruff check ore_filer tests
.\.venv\Scripts\python.exe -m pytest
```

`ruff`の設定はリポジトリに置かず、既定のルールを使う。`ruff format`はタブでインデントされたファイルの書式を崩すため実行しない。

SFTPの結合テストは、接続先のSSHサーバーを環境変数で指定したときだけ実行する（指定が無い場合は省略される）。

```powershell
$env:ORE_FILER_TEST_SFTP_HOST = "127.0.0.1"
$env:ORE_FILER_TEST_SFTP_PORT = "2222"
$env:ORE_FILER_TEST_SFTP_USER = "<ユーザー名>"
$env:ORE_FILER_TEST_SFTP_PASSWORD = "<パスワード>"
```

## 自動更新

`ore_filer/updater.py` に実装済み。

- **確認先**: GitHub Releases API `/releases/latest` を HTTPS で取得
- **確認タイミング**: 起動時にバックグラウンドで確認（1日1回）。`Ctrl+Shift+U` で手動確認も可
- **バージョン比較**: タグ文字列を `(major, minor, patch)` タプルに変換して比較
- **取得対象**: `ore-filer-Windows.zip` を優先。無い場合のみ `ore-filer.exe` を使う。zipから `ore-filer.exe` と `app-launcher\app-launcher.exe` を取り出す
- **UI**: 新バージョン検出時に確認ダイアログを表示し、ユーザーの承認後にダウンロード・上書きインストール
- **インストール**: 実行中の exe をリネーム（`.old`）して新しいものをコピー。`ore-filer.exe` と同じフォルダの `app-launcher\app-launcher.exe` も置き換える（フォルダが無ければ作成）。起動時に `.old` を自動削除
- **失敗時**: ネットワーク障害・キャンセルはアプリ起動を妨げない

| キー             | 操作               |

Git メニューのアクセラレータ:

| キー  | 操作                                          |
| ----- | --------------------------------------------- |
| `A` | ステージ（選択/カーソル項目を`git add`）    |
| `R` | ステージ解除（`git restore --staged`）      |
| `C` | コミット（ステージ済み一覧 + メッセージ入力） |
| `F` | fetch（リモートの参照を取得）                |
| `L` | pull（確認後バックグラウンド実行）            |
| `P` | push（確認後バックグラウンド実行）            |
| `D` | 差分（カーソルファイルの`git diff HEAD`）   |
| `G` | ログ（直近200件 → Enter で`git show`）     |
| `B` | ブランチ切替                                  |

ファイル行の左端に色帯で状態を表示する（橙: 変更、緑: 追加、灰: 未追跡、赤: 削除）。パス欄に `[git: ブランチ名]` を表示する。リポジトリ外のフォルダでは何も表示されない。Git操作はDulwichを使用するため、`git.exe`は不要。リモート操作はリポジトリに設定された`origin`を使用する。

現在のGit対応範囲は、状態確認、ステージ、ステージ解除、コミット、差分、ログ、ブランチ切替、fetch、SSH鍵またはssh-agentを使ったpush、およびfast-forward限定のpull。HTTPSの認証情報設定や複雑なマージ、rebase、stash、Git LFSは対象外。SSH鍵は`ssh-agent`、`core.sshCommand`、または`GIT_SSH_COMMAND`で指定する。

### Pキーのアーカイブ作成

- アクティブペインで選択中の項目を対象にする。選択がない場合はカーソル位置の項目を対象にする
- 保存先は反対側ペインの現在のフォルダー
- ファイル名と任意のパスワードを入力し、ファイル名の拡張子で形式を選択する
- 対応形式は `.zip`、`.jar`、`.apk`、`.7z`、`.tar`、`.tar.gz`、`.tgz`、`.tar.bz2`、`.tbz2`
- パスワードはzip/jar/apkまたは7zで設定できる。tar系でパスワードを入力した場合は作成できない
- 同名ファイルがある場合は上書き確認を表示する
- 作成処理はバックグラウンドで実行し、完了後に左右のペインを更新する

### Uキーのアーカイブ展開

- アクティブペインで選択中のアーカイブを対象にする。選択がない場合はカーソル位置のアーカイブを対象にする
- 展開先は反対側ペインの現在のフォルダー
- 実行前に確認ダイアログを表示する
- 対応形式は `.zip`、`.jar`、`.apk`、`.7z`、`.tar`、`.tar.gz`、`.tgz`、`.tar.bz2`、`.tbz2`
- 複数選択時は、すべて同じ展開先へ順番に展開する
- 展開処理はバックグラウンドで実行し、完了後に左右のペインを更新する
- LZH/RARは未対応

### アーカイブ内の閲覧とコピー

- 対応アーカイブにカーソルを合わせて`Return`を押すと、展開せずに内容をペインへ表示する
- アーカイブ内のフォルダーは通常のフォルダーと同じように`Return`で移動できる
- `Backspace`またはペイン端の`Left`/`Right`で親階層へ戻り、アーカイブ直下からは元のフォルダーへ戻る
- アーカイブ内のファイルやフォルダーを選択して`C`を押すと、反対側の通常フォルダーへコピーする
- パスワード付きzip/7zは、開くときにパスワードを入力する
- アーカイブをコピー先に指定することはできない

キー割り当ては後述のTOMLファイルから変更できる。

## リモート接続（SFTP）

`Ctrl+Shift+S` で接続ダイアログを開く。接続中にもう一度押すと切断する。

接続ダイアログ:

- ホスト、ポート、ユーザー名、初期フォルダを入力する。認証はパスワードまたは秘密鍵ファイルを使う。鍵を指定しない場合は ssh-agent と既定の鍵を試す
- 接続時に接続先プロファイルを `%APPDATA%\ore-filer\remote_profiles.json` へ保存する。プロファイル欄で選び直せ、削除ボタンで消せる。プロファイルにはパスワードを含めない
- 未処理の例外は `%APPDATA%\ore-filer\error.log` に追記される（配布exeはコンソールが無いため、クラッシュ時の調査用）
- 「パスワードを保存する」にチェックを入れると、パスワードをWindows資格情報マネージャーに保存する（サービス名 `ore-filer/sftp`）。資格情報マネージャーが使えない環境ではチェックボックスを無効にする
- ホストキーは `known_hosts`（システムの既定ファイル）で検証する。未登録のホストには接続しない

接続すると、アクティブペインに接続先のフォルダを表示する。接続先のフォルダは通常のペインと同じように移動できる。

転送:

| 組み合わせ | 操作 |
| --- | --- |
| ローカルのペインで選択 → 反対側がリモート | `C` でアップロード（反対側ペインのリモートフォルダへ） |
| リモートのペインで選択 → 反対側がローカル | `C` でダウンロード（反対側ペインのローカルフォルダへ） |

- 転送前に確認し、同名の項目がある場合は上書き確認を表示する
- 転送はバックグラウンドで実行し、画面はブロックしない
- 転送はSFTPのバイナリモードで行う。文字コードや改行コードを変換しないため、ファイルの内容はそのまま送られる
- リモート同士の転送、アーカイブとの間の転送はできない

## 外部キー設定

ユーザー設定は次の場所に保存する。

```text
%APPDATA%\\ore-filer\\keymap.toml
```

開発時の標準設定は`config/keymap.toml`に置く。初回起動時にユーザー設定がなければ標準設定を使用する。

```toml
[keys]
enter       = "Return"
parent      = "Backspace"
switch_pane = "Tab"
copy        = "C"
move        = "M"
rename      = "R"
drive       = "D"
quit        = "Q"
remote_connect = "Ctrl+Shift+S"
```

キーからPython関数へ直接接続せず、操作名を経由する。

```text
キー入力 -> 操作名 -> コマンド -> サービス
```

設定の読み込み時には次を検証する。

- 存在しない操作名
- 不正なキー表記
- 同じキーの重複
- 必須操作の欠落
- 壊れたTOML

設定が壊れている場合はエラーを表示し、標準設定で起動する。将来的には`Z`キーによる設定再読み込みに対応する。

## アプリランチャー連携

`L`で、登録済みアプリのダイアログ（アプリランチャー）を開く。アプリの登録と起動は外部CLIの`app-launcher`が行い、ore-filerはそのCLIをsubprocessで呼び出す。

起動対象は、アクティブペインでマークした項目。マークが無い場合は、ファイルを渡さずにアプリだけを起動する。カーソル項目は対象にならない。複数のファイルを選択した場合は、1つのアプリにまとめて渡す。

ダイアログの一覧タブ:

| キー      | 操作                                                         |
| --------- | ------------------------------------------------------------ |
| `↑` / `↓` | アプリを選択                                                 |
| `Enter`   | 選択したアプリを起動                                         |
| `→`       | アプリ設定タブへ切り替え                                     |
| 文字入力  | インクリメンタルフィルタ。名前に文字列を含むアプリだけ表示（`Backspace`で1文字削除、`Esc`で解除） |

`L`は、Gitメニュー内の`L`（pull）とは別の操作。

アプリ設定タブ:

- フォルダを登録元として追加し、配下のexeを検知する
- 再帰（サブフォルダも検知するか）は、登録後も切り替えられる
- 再スキャン、登録元の削除
- 検知したexeごとに、エイリアス編集と「一覧に表示」の切り替え（即時保存）。「一覧に表示」をOFFにしても、エイリアスでは起動できる
- 親フォルダを再帰登録すると、配下の登録元は親へ統合される。配下のフォルダを追加した場合は登録せず、親を再スキャンして通知する

設定と保存先:

- `app-launcher.exe`は、`%APPDATA%\ore-filer\config.json`の`app_launcher_path`（絶対パス）を優先する。未指定の場合は、ore-filerと同じフォルダの`app-launcher\app-launcher.exe`を使う。配布zipにはこのフォルダが含まれ、自動更新でも同じ場所の`app-launcher.exe`が新しくなる
- 登録データは`%LOCALAPPDATA%\app-launcher\apps.json`に保存され、`app-launcher`が管理する

## CLI

GUIとCLIは同じサービス層を利用する。CLIはGUIのペイン状態に依存せず、パスを明示的に受け取る。

```powershell
ore-filer list C:\Users\SatoshiｰOotomo\Downloads
ore-filer copy "C:\work\a.txt" "D:\backup"
ore-filer move "C:\work\a.txt" "D:\archive"
ore-filer rename "C:\work\a.txt" "b.txt"
ore-filer mkdir "C:\work\new-folder"
ore-filer delete "C:\work\a.txt" --recycle-bin
ore-filer search "C:\work" "*.py"
```

assist-chat連携用にJSON出力を提供する。

```powershell
ore-filer copy "C:\work\a.txt" "D:\backup" --json
```

```json
{
  "success": true,
  "operation": "copy",
  "sources": ["C:\\work\\a.txt"],
  "destination": "D:\\backup",
  "results": [
    {
      "source": "C:\\work\\a.txt",
      "target": "D:\\backup\\a.txt",
      "status": "completed"
    }
  ]
}
```

CLIの方針:

- `--json`: 機械可読な結果を標準出力へ出す
- `--dry-run`: 実際には変更せず実行内容だけ確認する
- `--yes`: 削除や上書きを明示的に許可する
- 成功・失敗を終了コードで通知する
- 通常の結果は標準出力、エラーは標準エラー出力へ出す
- 削除・上書きは暗黙に実行しない

## Pythonプラグイン

プラグインは次の場所から読み込む。

```text
%APPDATA%\\ore-filer\\plugins\\
```

プラグインは安定した公開APIを利用し、Qt内部のウィジェットを直接操作しない。

```python
from ore_filer.api import Command


class SampleCommand(Command):
    command_id = "sample.show_message"
    label = "サンプルメッセージ"

    def execute(self, context):
        context.notify("プラグインから実行しました")


def register(app):
    app.commands.register(SampleCommand())
```

公開APIの候補:

- アクティブペインの取得
- 左右ペインのパス取得
- 選択ファイルの取得
- ファイル一覧の更新
- コピー・移動・削除
- ブックマークの追加・取得
- 通知・ログ出力
- コマンド登録
- メニュー追加
- キー割り当て追加
- 外部コマンド起動

プラグインは任意のPythonコードを実行できるため、初期版ではユーザーが明示的に配置したディレクトリのプラグインだけを読み込む。

## GUI、CLI、プラグインの関係

```text
cfiler互換キー
       |
       v
    コマンド層 <----- CLI
       |
       v
  共通サービス層 <--- Pythonプラグイン
       |
       v
  ファイルシステム
```

GUI、CLI、プラグインがそれぞれ独自にコピーや削除を実装しないことが重要。ファイル操作の安全確認、エラー処理、進捗通知は共通サービス層に集約する。
